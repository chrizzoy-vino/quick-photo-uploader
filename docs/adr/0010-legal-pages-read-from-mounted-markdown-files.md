# Legal pages (Impressum/Datenschutz) are read from mounted markdown files, not env vars or hardcoded content

The Impressum and Datenschutzerklärung pages need real, operator-specific content (name, address, contact, a GDPR-compliant description of what's processed) once the app runs beyond a private circle — but that content must never end up in the public git repo or the public GHCR image, since both now contain only generic, shareable code. Considered and rejected: hardcoding the real text directly in `app/impressum/page.tsx` / `app/datenschutz/page.tsx` (would leak the operator's PII into the public repo and image); passing the full text through environment variables, like `ADMIN_SECRET` (workable for a few short Impressum fields, but awkward for multi-paragraph, multi-heading legal prose — env vars don't handle long-form structured text well). We chose to read `data/content/impressum.md` and `data/content/datenschutz.md` (path configurable via `CONTENT_ROOT`, defaulting to `./data/content`) at request time, rendered with `marked`, reusing the same `./data` volume that already holds the database and album files (see ADR-0002) rather than adding a second bind mount. If a file is missing, the page falls back to today's placeholder instead of failing. Consequence: these two pages are excluded from Next.js's static prerendering (`export const dynamic = 'force-dynamic'`), since the content lives outside the build and can change without a redeploy.
