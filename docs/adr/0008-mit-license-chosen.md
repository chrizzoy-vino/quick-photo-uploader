# MIT license chosen despite the deliberately open security model

We made the repository public and needed to pick a license. Considered and rejected: publishing the source as public-but-all-rights-reserved (viewable as a portfolio piece, but no reuse rights) and publishing with no license file at all (which defaults to "all rights reserved" anyway, just implicitly). We chose MIT — the simple, common choice for a hobby/portfolio repo — over the more restrictive option specifically because this app's security model is intentionally minimal for its own private, link-only use case (see ADR-0001, ADR-0003, ADR-0006): anyone who forks and self-hosts it takes on those documented trade-offs themselves, for their own use case, rather than inheriting an ambiguous "look but don't touch" license that would discourage even that.
