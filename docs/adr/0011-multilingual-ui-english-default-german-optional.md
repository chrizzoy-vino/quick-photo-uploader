# Multilingual product UI: English default/fallback, German switchable, no URL change

ADR-0009 kept the product UI German-only, reasoning that ADR-0001's target audience (non-technical, WhatsApp-shared albums) is recognizably German-speaking. That's superseded now: the UI (homepage, album view, upload/gallery/dialogs, and the Impressum/Datenschutz placeholder text - not the operator's real legal content, which stays single-language per ADR-0010) is bilingual, English default with German switchable via a 🌐 icon. The admin area (`/admin`) is the one exception: it stays a single fixed language, switched from German to English, since it's used only by the operator, not the app's actual audience - translating it bilingually would be pure overhead. We chose no URL-based locale routing (no `/en/`, `/de/` prefix, no `[locale]` route segment): album links like `/wedding-anna` are already shared via WhatsApp and must keep working unchanged, so the locale is resolved from a cookie (set by the switcher) or, on a first visit, the browser's `Accept-Language` header, read server-side to avoid a flash of the wrong language. We used `next-intl` rather than hand-rolling this - SSR-safe cookie/header negotiation, ICU message interpolation (e.g. "Already uploaded by {name}"), and pluralization are exactly what it's for, and getting those details right by hand is easy to get subtly wrong. Auto-generated display names (e.g. "Fröhlicher Pinguin" / "Happy Penguin") are also locale-aware for the same reason a mismatched UI language would be: consistency for whoever's actually looking at the screen.
